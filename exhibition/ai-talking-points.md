## 一行で

---

## LLM 以前 / 以降で体験はこう変わった

Reminq の主張は「リマインダーアプリの**最大の弱点が LLM で初めて解ける**」というもの。

| 観点 | LLM 以前のリマインダー | Reminq（LLM 以降） |
| --- | --- | --- |
| 大きなタスク | 「資料を作る」と書いて止まる | 1 行 → 実行可能なステップ群へ自動分解 |
| 粒度 | ユーザーが毎回考える | LLM が下案、ユーザーは採否だけ |
| 優先度 | 自分でソート、後で混乱 | High / Mid / Low を分解と同時に提案 |
| 着手 | 「何から？」で詰まる | 常に「最初の一歩」が用意されている |
| 振り返り | 完了タスクが文字列のまま流れる | カンバン × グラフで「止まりやすい型」が可視化 |
| ポジション | フラットなリストの管理ツール | **タスクを読み解く相棒** |

ポイントは、**LLM がタスク管理の「入力欄」から「読み解き層」へ昇格**したこと。書いた瞬間に止まるタスクは、人間の意志ではなく**粒度設計の不在**が原因だった、という再定義。

## アーキテクチャ

### データフロー

```
                    ┌──────────────────────────┐
                    │   ユーザー端末 (iOS/iPadOS/macOS)   │
                    │                                    │
   ┌───────────────▶│  Reminq.app                        │
   │   ユーザー入力  │   ├─ Kanban UI                     │
   │                │   ├─ AI 提案レビュー UI            │
   │                │   └─ 付箋カメラ (Vision)           │
   │                │            │                       │
   │                │            │ 1 shot 構造化生成     │
   │                │            ▼                       │
   │                │   OpenAI Chat Completions          │◀──┐
   │                │            (端末から直接)            │
   │                │            │                       │   │
   │                │   分解ステップ + 優先度 (JSON)      │   │
   │                │            │                       │   │
   │                │            ▼                       │   │
   │                │   Apple リマインダー (EventKit)     │   │
   │                └────────────┬─────────────────────────┘   │
   │                             │                             │
   │                             │ iCloud で純正同期           │ BYO
   │                             ▼                             │ APIキー
   │              iPhone / iPad / Mac / Apple Watch           │
   │                                                          │
   └─────── ユーザー所有の OpenAI アカウント ──────────────────┘
```

### 構成要素と境界

- **データの真実 (Source of Truth) = Apple リマインダー**
  - すべてのタスクは EventKit を介して Apple のリマインダーに書き込まれる
  - Reminq は「ビュー兼 LLM 入口」であって、独自のデータベースを持たない
  - **アプリを消してもタスクは残る** — ユーザー視点でロックインがゼロ
- **Reminq バックエンド = 存在しない**
  - 中継サーバー、ユーザーアカウント、認証基盤、ログ収集 — どれもない
  - 攻撃面が極端に小さい / 運用コストが定数 0
- **LLM 呼び出し = 端末 → OpenAI へ直通**
  - プロンプトもタスク内容もアプリ運営者を通らない
  - レイテンシは「端末の回線 + OpenAI の応答」のみ
- **API キー = ユーザー所有 (BYO)**
  - 課金はユーザーの OpenAI アカウントから直接
  - モデル選定もユーザー側に開放

### このアーキテクチャの帰結

- **プライバシーポリシーが短い**: 外部送信は AI 利用時のみ、宛先はユーザー自身のキーで叩く OpenAI
- **コストが運営にスケールしない**: ユーザーが増えても LLM コストは Reminq に乗らない
- **モデルの世代交代に強い**: 互換 API なので、より良いモデルが出れば**ユーザーが切り替えるだけ**で体験が更新される
- **オフラインで普通に動く**: AI 機能だけがネットを必要とする。中核のリマインダー操作は端末完結

## LLM の使い方（プロンプト・構造化出力）

- **入力**: リマインダーのタイトル文字列（例: 「資料を作る」）
- **出力**: ステップ配列 + 各ステップへの優先度ラベル（High / Mid / Low）を**同一レスポンスで構造化**
- **設計上のキモ**:
  - 分解と優先度を別呼び出しにしない → **1 ラウンドトリップ**でレイテンシとトークンを節約
  - モデルに「順序の根拠」を持たせたまま優先度付けさせる（後付けの優先度は文脈を失う）
  - レスポンスは UI コンポーネントへ直接バインド可能な形に整形
- **マルチモーダル入口**: 付箋カメラ取り込みは「紙 → 構造化タスク」のパイプラインで、Vision 系処理 → リマインダー化

## 設計判断（トレードオフを正面から）

- **なぜ Human-in-the-loop か**
  - LLM 出力をリマインダーへ直接書き込まない。チェックボックスで採用したものだけ反映
  - **ハルシネーションを UX 破壊に翻訳しない**ための構造的な防壁
  - 「AI 出力 = 破棄可能な下書き」と扱えば、モデルが多少外しても許容できる
- **なぜ BYO API キーか**
  - 集約バックエンドを持たない覚悟と裏表
  - ユーザーは料金・モデル・利用ログをすべて自分の手元で見られる
  - トレードオフ: 初回セットアップに API キー取得のひと手間が必要
- **なぜ Apple リマインダーに張り付くのか**
  - 自前 DB を作るとユーザーをロックインする。それは LLM 体験の主役ではない
  - リマインダーは Apple が無料で提供する全プラットフォーム同期基盤。乗らない理由がない
  - LLM の役目は「リマインダーを読み解く層」に専念

## 周辺機能（補助線）

- **カンバン (TODO / 進行中 / 完了)** — LLM が分解したステップを優先度付きで配置、ドラッグで状態遷移
- **アクティビティ解析** — 週次・月次グラフ。AI 分解と組み合わせると「止まりやすい型」がデータで見える
- **GitHub Issue 変換 (ベータ)** — リマインダーをワンタップで Issue へ。開発者向けの応用ユースケース
- **ホーム画面ウィジェット** — タスク状況を一目で
- **多言語**: 日本語 / English
- **対応 OS**: iOS 26+ / iPadOS 26+ / macOS 26+
- **完全無料・サブスクなし**

## 想定 QA（チートシート）

- 「モデルは？」 → OpenAI Chat Completions 互換。BYO 方式なのでユーザーの選択
- 「プロンプトは？」 → タスク文字列 → ステップ配列 + 優先度を 1 ショットで返させる構造化生成
- 「ハルシネーションは？」 → 反映前にチェックが必須なので「下書き」扱いで無害化
- 「サーバー側に送られる？」 → Reminq の中継は存在しない。AI 通信はユーザー → OpenAI 直通
- 「課金は？」 → アプリは完全無料。AI 利用時のみユーザー自身の OpenAI アカウントから従量課金
- 「将来 Anthropic / ローカルモデル対応は？」 → アーキテクチャ上、OpenAI 互換クライアントを差し替える形で実装可能（現時点では OpenAI のみ）
